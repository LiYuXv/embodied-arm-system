# SmolVLA 模型训练主要要点（ela3 真机经验总结）

> 本文汇总 2026-08 期间 SmolVLA/SmolVLA-torque 在 ela3 机械臂上的训练-评估-部署
> 分析结论，重点是**模型输出往复运动（来回运动/原地抖动）的定性与定量根因**，
> 以及对应的训练与推理侧对策。相关数据问题修复史见 `数据问题分析.md`，
> 训练/推理命令见 `TRAIN_README.md`。

---

## 1. 离线评估的正确认识（teacher-forcing 陷阱）

离线推理测试（`test_inference_episode.py`）每帧喂给模型的是数据集的**真值 state**，
而 action 标签是下一帧位姿——20fps 下每帧运动量极小：

| 指标 | mean abs err |
|---|---|
| **"原地不动"基线**（pred = 当前 state） | **0.0041** |
| 双路模型（18K 步 checkpoint） | 0.0291 |
| 全盲模型 | 0.0616 |

**结论**：

- 离线 mean abs error **区分度很低**：什么都不输出都比模型"好"。不能用它单独
  判断模型好坏（问题 5 的恒等映射模型也是靠这个指标骗过人的）。
- 有效的离线判据：**摄像头消融差异**、**换图像对照实验**、**chunk 轨迹质量**
  （路径/净位移比，见第 3 节）。

## 2. 输入通道贡献（消融实验，18K checkpoint，episode 5，seed=1000）

| 模式 | mean abs err | 判读 |
|---|---|---|
| 双路 + 力矩 | **0.0291** | 基准 |
| 仅 cam2（cam1 置黑） | 0.0422 | 缺 cam1 +45% |
| 仅 cam1（cam2 置黑） | 0.0522 | 缺 cam2 +79%（cam2 更关键） |
| 双路置黑（全盲） | 0.0616 | 视觉总体贡献显著（+112%） |
| 力矩置零（ep5/ep30） | 0.0345/0.0354 vs 真实 0.0308/0.0283 | **力矩提升 11%~20%** |

要点：

- 两路摄像头**都被使用且互补**；cam2 贡献更大。缺哪路误差升得越多，哪路越重要。
- 力矩已被模型真正利用（置零后输出变化 mean|Δ|=0.028，远大于噪声底噪），
  **部署时必须保证真实力矩输入**（缺力矩=分布外输入，性能退化）。
- 全盲仍有"大趋势"是 state/任务文本/数据先验 + teacher-forcing 的假象，
  不构成"模型学会作弊"的证据。

## 3. 往复运动（来回运动）的根因分析

### 3.1 现象（"推理一次"68 次单次执行日志）

| 指标 | 模型输出 chunk（40 帧目标） | 机械臂实际反馈 |
|---|---|---|
| 路径长/净位移 | **mean 4.34，中位 3.56，最大 19.2** | mean 1.90 |
| 反向步数（/38 步） | mean 10.0，**≥8 步占 74%** | mean 5.1 |
| 净位移 | mean 58mm | mean **5.0mm** |
| 目标-反馈跟踪误差 | — | mean 33mm |

模型规划的目标轨迹本身就是来回摆动的；执行端 EMA 把往复目标平均后，
机械臂表现为"原地抖动、到不了目标、又被拉回起点附近"。

### 3.2 责任划分

| 环节 | 路径/净位移（40 帧窗口） | 结论 |
|---|---|---|
| 训练数据 GT（示教轨迹） | **1.36~1.65（p90 2.4）** | **数据干净，无往复** |
| 模型推理输出 | 3.6~4.3 | **摆动是模型生成的** |
| 运动层/PD 控制/结构晃动 | 反馈 1.9（比目标更平滑） | 放大抖动但非根源 |

**根源 = flow-matching 采样方差 >> 每步运动量**：

- 训练标签 `action[t]=state[t+1]` 的每帧增量仅 ~4mm（7 维混合单位均值 0.004），
  而模型采样噪声幅度 ~10mm，**信噪比 ~1:2.5**，输出摆动不可避免；
- 叠加训练量不足：82K 帧 × batch16 × 18K 步 ≈ **3.5 epoch**（每个样本只见 3.5 次），
  模型对轨迹置信度低，每次采样在不同候选方向间摇摆。

### 3.3 缓解手段实测（离线，同帧同种子对比 chunk 摆动度）

| 方案 | 路径/净位移 | 评价 |
|---|---|---|
| 默认（num_steps=10） | 3.87 | 基准 |
| num_steps 10→25 | 3.56 | **几乎无用，不必改** |
| **3 次采样取平均** | **2.73（-30%）** | 推理侧最有效 |
| 多次采样固定种子 | 仅可复现，不减摆动 | 用于公平对比 |

## 4. 对策清单（按杠杆排序）

### 训练侧（治本，需重训）

1. **action 标签大跨度化（杠杆最大）**：`action[t]=pose[t+N]`，N=5~10
   （20fps 下领先 0.25~0.5s）。每步目标增量 4mm→20~40mm，信噪比翻 5~10 倍。
   - 新录制：采集界面"前瞻帧"（默认 5，范围 1~20，录制期间锁定）原生写入；
   - 旧数据：`python3 fix_action_labels.py --root <数据集> --lookahead 5` 统一转换；
   - **严禁混训不同 N 的数据**。
   - 注意：执行速度不变——逐帧下发 `pose[t+5], pose[t+6]...` 仍跟踪示教轨迹。

   **lookahead 的机理（不损失精细性、不放大运动距离）**：
   chunk 内 40 个动作是 `pose[t+5], pose[t+6], …, pose[t+44]`，相邻动作仍差 1 帧
   （~4mm），chunk 覆盖的仍是约 2s 示教轨迹——**每次推理的运动距离、执行速度、
   位姿分辨率都不变**。真正改变的是"当前观测 → 首个目标"的距离（4mm→20mm）：
   信号不再被采样噪声淹没，且模型无法退化为"输出≈当前位姿"的恒等映射，
   被迫用视觉/任务预判方向。附带好处：0.25s 前瞻恰好补偿推理+响应延迟。
   （注意区别于跳步采样 `action[k]=pose[t+5k]`——那种方案才 5 倍速、损失精细性，
   我们没有采用。）

   **N 取 5 还是 10：先用 5**。

   | | N=5（0.25s） | N=10（0.5s） |
   |---|---|---|
   | 首步目标增量 | ~20mm（信噪比已够用） | ~40mm |
   | 预测难度 | 低 | 高（变向/抓取瞬间误差大） |
   | 夹爪时机错位 | 0.25s 可接受 | **0.5s 易"没到位就夹"** |
   | 首帧跳变 | 20mm，低通后平滑 | 40mm 有可感小跳 |

   若 N=5 重训后 chunk 摆动比未降到 ~2 以下，再试 10；录制与转换的 N 必须一致。
2. **增加数据量与均衡任务**：move two boxes 仅 24 条 vs clear the desktop 96 条，
   补录到各 50+；剪辑犹豫/原地修正片段（可视化工具"数据集检查"可看静止帧占比）。
3. **训练步数**：18K → 30K~40K（3.5 → 6~8 epoch）；数据量优先于 epoch 数。
4. **图像增强**：`image_transforms.enable: true`（只开亮度/对比度，几何变换慎用），
   提升对真实相机曝光漂移的鲁棒性。
5. **验证集**：`eval_split: 0.05` 监控过拟合。

### 推理侧（立即可用）

6. **多次采样取平均**（同一观测采 3~5 次 chunk 逐帧取平均，逼近分布中心，
   实测 -30% 摆动；代价是推理耗时 ×N，RTC 异步可隐藏）。
7. **执行端低通**：界面"低通滤波"开关（默认开），段端点 EMA 系数 α 默认 0.8
   （α=0.5 实测闭环速度近折半，详见第十节）；RTC 已重写为管道平滑块执行
   （段间插值拼接 + 往复抑制滤波，见第十节，软融合机制已移除）。
8. **任务文本必须与训练一致**（clear the desktop / move two boxes to the yellow ares）。

### 执行/硬件侧（等模型输出干净后再评估）

9. PD 控制与结构晃动影响的是**到位精度**（目标点附近 ±几 mm 振荡），
   不产生大尺度往复；若残差存在再调 PD 增益/到位判稳。

## 5. 关键概念澄清

- **epoch**：模型完整看一遍数据集为 1 epoch。18K 步 × batch16 = 288K 样本 ÷ 82K 帧
  ≈ 3.5 epoch；VLA 类模型常见量级为几十~上百 epoch（前提是数据量够，否则过拟合）。
- **采样噪声**：flow-matching 每次推理从新高斯噪声出发去噪，同输入输出不同；
  与机械臂物理误差无关。固定种子可复现（同种子两环境逐位一致），但不减摆动。
- **多次采样平均**：观测（图像/位姿/力矩）只取一次，重复采样的是模型内部噪声；
  N 段 chunk 逐帧平均抵消随机摇摆，等价于对动作分布求中心。
- **512×512 输入**：1280×720 经 letterbox（缩放+补边，非拉伸）为 512×288 有效画面，
  训练/推理一致，不是失配问题；相机不要改 512×512（中心裁切会缩视野）。
  分辨率是 SmolVLA 固有能力上限，非当前主要矛盾。

## 一、故障现象

1. 选择 `ckpt/act_ela3_real` 文件夹后模型能加载、能推理（状态栏显示"推理中"），但**点击"开始推理"后机械臂完全不动**。

3. 初步修复后机械臂能连续运动了，但**动作非常剧烈、猛冲**。

## 三、修复一：ACT 模型接入（前置工作）

原 GUI 只支持 SmolVLA。ACT 与 SmolVLA 推理路径的差异及处理：

| 差异点 | SmolVLA | ACT（修复后处理） |
|---|---|---|
| 归一化 | 外部 `policy_preprocessor/postprocessor.json` | 无外部处理器，跳过加载 |
| `_get_action_chunk` 方法 | 有（用于多次采样平均包装） | 没有 → 包装加 `hasattr` 保护，否则 `AttributeError` |
| state 维度 | 7 维（力矩独立键） | 8 维，力矩拼接到 state 末尾 |
| task 文本 | 需要 | 不需要（ACT 无任务条件） |
| 图像尺寸 | preprocessor 内部处理 | 推理侧显式 `cv2.resize` 到 512×512 |

实现方式：`VLAInferenceThread.run()` 读取 checkpoint `config.json` 的 `type` 字段自动识别 `"act"`；新增 `_build_batch()` 集中处理上述差异；普通/RTC/「推理一次」三条路径共用。

## 四、故障一：连续推理机械臂不动

### 4.1 排查过程（排除法）

1. **手柄抢控制权（第一嫌疑，后被排除）**：手柄连接时 `XboxArmController` 以 100Hz 直接调 `arm.JointCtrl` 保位（绕过 worker 队列），会覆盖 VLA 的 20Hz 指令。已加"启动推理即自动接管控制权"修复。但**用户确认手柄未连接**，问题依旧 → 排除。
2. **观测缺失**：`_vla_get_obs()` 返回 None 时推理循环静默空转。已加"等待有效观测"可见提示。真机上观测正常（「推理一次」能动可证）→ 排除。
3. **控制暂停位**：`_vla_control_paused` 卡 True 会丢弃动作。核查所有置位路径（手柄互锁/单次执行）→ 启动时为 False → 排除。
4. **无头复现**：用假观测驱动 `CameraWidget` 全链路测试，普通/RTC 模式均有 700+ 次 `end_pose_ctrl` 下发 → **动作流确实到达了机械臂 worker** → 问题在 SDK 执行侧。

### 4.2 真正根因：MoveJ 保位段 + 轨迹替换 + 20Hz 下发

普通模式（未勾 RTC）旧代码下发参数为 `servo=False`，走 SDK `MoveJ` 路径，三个机制叠加导致机械臂**永远不动**：

```
SDK MoveJ（控制循环模式）每段轨迹结构：
┌──────────────┬─────────────────────────┐
│ 50ms 保位段   │  S 曲线运动段            │   ← 保位段：保持当前反馈位置不动
└──────────────┴─────────────────────────┘

_execute_trajectory_async：新轨迹【直接替换】旧轨迹（_traj_index 清零重计）

VLA 20Hz 下发 = 每 50ms 来一条新 MoveJ：
t=0ms    轨迹A开始 → 处于保位段
t=50ms   轨迹B替换A → 重新进入保位段      ← A 的 S 曲线段永远没执行到
t=100ms  轨迹C替换B → 重新进入保位段
...      机械臂永远处于某段轨迹的前 50ms 保位段内 → 完全静止
```

**为什么「推理一次」能动**：单段 chunk 的 10 条命令发完后没有新命令再来替换，最后一条命令的保位段结束后 S 曲线完整执行 → 机械臂运动到 chunk 末端位姿。这就是"点一下动一下"的原因。

**为什么 RTC 模式一直正常**：RTC 走 `servo=True` 的伺服流（`_servo_stream`），关节空间线性插值上采样到 200Hz，**没有保位段**——此前 SmolVLA 一直勾着 RTC 用，所以从没踩到这个坑。

### 4.3 修复

`_dispatch_vla_action()` 中 `end_pose_ctrl` 的 `servo` 参数由 `self._rtc_mode` 改为恒 `True`（SDK 伺服流本来就是为 ≥20Hz 连续下发设计的）。

---

## 五、故障二：修复后动作剧烈、猛冲

### 5.1 根因

`servo=True` 的 20Hz 逐点滴灌虽然能让臂动，但每 50ms 一段的线性插值，其速度前馈为 `Δq / 0.05s`。而 ACT 输出存在 **chunk 边界跳变**（开环执行 10 步后重新推理，新 chunk 首帧与上一段尾帧不连续，离线评估图上可见明显锯齿），每个边界都在 50ms 窗口内被放大成一次**速度脉冲** → 宏观表现就是动作猛烈、抖动。

### 5.2 最终方案：顺序块执行（类 MoveJ 插值）

按"参考推理一次、像 MoveJ 一样插值、执行完一轮再推理下一轮"的要求，普通模式重写为**顺序块执行**：

```
推理整段 chunk(10 步)
   ↓
取 chunk 末端位姿，一次性下发 end_pose_ctrl(servo=False)
   → SDK MoveJ：S 曲线插值（加速度受限、平滑启停），整段只发一次
   ↓
夹爪按 chunk 内序列 20Hz 滴灌跟随（开合时机不丢失）
   ↓
执行窗口（0.5s）结束 → 推理下一段 → 执行 → 循环
```

要点：

- **每 0.5s 只有一条完整 S 曲线**，从机制上消除了 20Hz 滴灌的边界猛冲；新段到来时旧 S 曲线若未走完，从当前反馈位置重新规划（位置连续 + 50ms 保位段过渡）。
- **安全限幅**：每段末端位置跳变 ≤ 10cm（`_seq_max_jump`）、姿态 ≤ 0.6rad（`_seq_max_rot`），沿当前位姿方向等比缩放，防异常输出猛冲。
- **「推理一次」同步改造**：主运动同样一次 MoveJ 到位；20Hz 定时器只保留夹爪跟随和目标/反馈日志（诊断能力不变，仍存 `inference_once_logs/<时间戳>/`）。
- **暂停/恢复/停止适配**：暂停时停止调度定时器（已下发的 MoveJ ≤0.6s 自然走完）；恢复时基于最新观测立即请求新 chunk。
- 推理线程统一为"按需 chunk 推理"循环（`predict_action_chunk`），普通/RTC 共用；普通模式不再逐帧 `select_action` 滴灌。
- **RTC 模式（当时）**：异步执行 + 软融合，`servo=True` 滴灌。
  （注：该旧 RTC 后来因"太快、不平滑"被重写，见第十节。）

## 八、经验与注意事项

1. **20Hz 设定点流不能用 `servo=False`（MoveJ）下发**：SDK MoveJ 的 50ms 保位段 + 轨迹替换机制决定了它只适合一次性运动指令，不适合连续滴灌。连续流式控制必须走 `servo=True` 伺服流，或像本方案一样按 chunk 一次性下发。
2. **ACT chunk 边界跳变是真实存在的**（离线评估 rz 维度可见 ±0.2~0.4 rad 锯齿），执行侧必须做整段插值或时序集成/软融合，不能逐点直发。
3. **顺序块执行 vs RTC**：顺序块平滑但有段间微停顿（S 曲线归零速 + ~50ms 推理）；RTC（管道平滑块）无停顿且同样平滑。日常首选 RTC，精度/诊断优先用普通模式或"推理一次"（详见第十一节对比表）。
4. 可调参数：`_seq_max_jump`（每段最大位移，默认 0.10m）、`_seq_max_rot`（每段最大姿态变化，默认 0.6rad）、`_lerobot_fps`（20Hz，决定执行窗口 0.5s）。
5. 若以后想用中间检查点，直接把完整路径填进模型框，如 `./ckpt/act_ela3_real/checkpoint_step_18000`。
6. **注意：本节第五节的"RTC 模式不变"描述已过时**——RTC 已于 2026-08-17 重写为"管道平滑块执行"，最新设计见后文第九~十一节。

## 九、SmolVLA 往复运动与执行方式的关系（2026-08-17 答疑分析）

问题：SmolVLA 普通模式推理出现来回运动，是否与 ACT 排查中的控制权竞争有关？是否与 MoveJ 有关？

**结论 1：与控制权竞争无关。** 控制权竞争（手柄 100Hz 保位循环覆盖 VLA 指令）的表现是"被拉住不动/被拽回固定点"，且启动推理时已会自动断开手柄控臂。往复的根源仍是第 3 节的模型侧结论（flow-matching 采样信噪比 ~1:2.5，输出 chunk 本身摇摆）。

**结论 2：MoveJ 不是根源，但执行方式是"显影剂"。** 同一模型的摆动输出，不同执行方式的外在表现完全不同：

| 执行方式 | 对模型摆动的处理 | 真机外在表现 |
|---|---|---|
| 20Hz 滴灌 + EMA α=0.5 | 往复目标被滑动平均 | 原地小幅抖动 |
| 顺序块执行（每段一次 MoveJ 到端点） | 每次方向反转被完整执行 | 大幅度平滑往复摆动 |
| 单端点取值（chunk 第 10 步） | 采样噪声最大的取法 | 进一步放大摆动 |

启示：**评估执行方式优劣时必须用同一模型同一观测对比**，否则会把模型侧的摆动误算到执行侧头上，或反之。

## 十、RTC 模式重写：管道平滑块执行（2026-08-17）

### 10.1 旧 RTC 的问题（动作队列 + 软融合 + 20Hz 逐点伺服滴灌）

- 每 50ms 一个伺服段，速度前馈 Δq/50ms，SmolVLA 采样噪声使逐步目标抖动 → **速度脉冲式晃动**；
- 5mm/步@20Hz 的限速口径偏快且每步重算 → 真机表现为**运动太快、不平滑**。

### 10.2 新设计（相当于两个"推理一次"之间做插值拼接）

```
段 k 执行中（0.5s servo 插值，还没走完）
   ↓ 窗口结束前 (实测推理延迟+40ms) 提前触发
采集最新图像+力矩 → 推理段 k+1
   ↓ 推理完成立即下发
servo 流从【当前设定点】200Hz 线性插值到段 k+1 端点 → 位置连续拼接，无停顿
```

每段处理链：

- **端点取值**：chunk 截断 10 步（0.5s 窗口），取**末 3 步均值**（单端点是采样噪声最大的点）；
- **段间 EMA**：平滑α 当前默认 0.8（α 越小越平滑但闭环速度越慢：α=0.5 实测速度近折半，因目标点持续落后模型输出一段形成"追赶滞后"平衡）；
- **速度封顶**：段位移 ≤ 步长mm × 10 步（当前默认 8mm → 80mm/段）；
- **夹爪**：chunk 内序列 20Hz 滴灌，保持段也照常跟随（抓取时机不丢）；
- **提前调度**：窗口结束前 latency+40ms 触发下一段推理；窗口 0.5s 恒大于 SmolVLA 延迟 ~0.3s，管道不空转。

### 10.3 速度模型（调参核心）

**执行速度 ≈ 段位移 ÷ 0.5s**，上限 = 步长mm × 20：

| 步长mm | 速度上限 |
|---|---|
| 5 | 0.10 m/s |
| 8（默认） | 0.16 m/s |
| 10 | 0.20 m/s |

演示中慢的相位（接近/抓取）位移小自然慢，搬运相位自然快——**固定窗口忠实保留示教节奏**；觉得慢就调大步长mm，不要缩短段窗口（见 10.4 的教训）。

**第二提速杆：目标步N（`_rtc_target_step`，界面旋钮）**。段目标取 chunk 第 N 步
（末 3 步均值），窗口仍固定 0.5s：N=10 为 0.5s 前瞻原速跟踪；N=14~20 瞄准更远
未来点 → 约 1.4~2 倍演示速度。前瞻越远预测误差越大，由限幅/EMA/往复抑制兜底。
（ACT chunk=10 时 N>10 无效；SmolVLA chunk=40 可用到 20+。）

### 10.4 失败教训：段时长自适应缩短（勿复用）

曾尝试"段时长 = 段位移 ÷ 速度"（小位移走 0.15s 短窗口），真机立即出现**卡顿+晃动+往复**三并发：

- **卡顿**：短窗口（0.15s）< SmolVLA 推理延迟（~0.3s）→ 每段走完后机械臂空等下一段；
- **晃动**：每秒 4~7 次段边界（每段匀速斜坡、边界速度阶梯）→ 回到接近 20Hz 滴灌的边界密度；
- **往复**：窗口越短每段位移越小，新推理从近静止状态采样，多模态方向摇摆被忠实执行。

**教训：段窗口必须 ≥ 推理延迟 + 裕量；提速靠位移上限，不靠缩短窗口。**

### 10.5 方向单调性约束（往复抑制，2026-08-17 第三轮：投影剥离）

**用户观察**：机械臂所有关节出现来回运动。用户分析：推理 chunk 40 步 A→E，
臂执行到中途 C 时发起下一次推理，新 chunk 起点在 D——两轮结果插值出现
"E→D 回退"。**判定**：方向正确；当前实现已是"从当前位置插补到新目标、放弃
E 点"，残留回退的真实来源是：① 新目标（含采样噪声 ±10~30mm）落在当前位置
**身后**且超阈值被执行；② **姿态通道此前完全没有反向滤波**——位置不回退、
姿态回退，经 IK 映射就是"各关节来回动"；③ 防锁死逃逸会周期性放行一个反向段。

**最终方案（投影剥离，替代此前的"保持"滤波）**：

1. 把每段位移/姿态增量沿**已建立的运动方向**分解，若存在反向分量：
   **剥掉反向分量、保留侧向修正**——主方向运动严格单调，侧向纠偏不受影响；
2. 位置与姿态**独立处理**（各自的方向基准与阈值）；
3. **真实反向放行**：位移 > 40mm（`_rtc_genuine_rev`，放置后撤退）或姿态
   > 0.25rad（大姿态调整）直接执行；
4. **慢速真实撤退放行**：连续 6 段（~3s）被剥离仍坚持反向 → 放行一次；
5. 被剥离的段不更新方向基准（噪声不被记忆）。

**两个实现教训（单元测试逮住）**：

- 方向基准必须从"**实际下发的运动**"（目标−当前位姿）更新，不能从"目标序列差"
  （tail−last_sent）更新——EMA 后目标可能落在当前位置附近，目标序列差会把
  基准污染成反向，导致后续**前向段被误剥**；
- 投影剥离不能设"最小位移门槛"——3~6mm 的混合方向小段同样藏着反向分量。

相比"保持不动"式滤波的优点：不冻结侧向运动、无锁死风险、主方向严格单调。

### 10.6 夹爪反复开合（2026-08-17 第二轮）

**现象**：臂部平滑后，夹爪在"该不该夹"的决策点附近反复开合。

**根因**：flow-matching 采样摇摆同样作用于夹爪通道——相邻 chunk（每 0.46s 一段）
的夹爪序列互相矛盾（一个说该闭、一个说还开）；而夹爪滴灌通道刻意不做插值
（避免拖慢开合时机），每段新 chunk 整体替换序列从第 0 步重发 → 随 chunk 交替开合。

**修复（滴灌 tick 内防抖，普通/RTC/推理一次共用）**：

- **死区**（`_grip_deadband` = 0.04rad）：与上次实际下发值变化小于死区 → 跳过；
- **换向驻留**（`_grip_rev_dwell` = 0.5s）：开→闭/闭→开换向须持续 0.5s 才执行，
  瞬时摇摆被抑制，持续的真实开合意图只延迟 ~0.5s。

真机验证前单元测试：微变/瞬时反向全抑制，持续反向延迟后放行，放行后同向续行正常。

### 10.7 观测时滞回拉与 d 步丢弃（2026-08-17 第三轮，用户定位）

**现象**：各关节出现来回运动。用户分析定位（正确）：chunk 观测采集于请求时刻，
推理完成到达时机械臂已走过 d=latency×fps 步（SmolVLA 0.3s≈6 步）；若段目标
取 chunk 第 N 步（=过期观测+N 步），相对当前位置只剩 N-d 步前瞻甚至落在身后
（"c 点执行中新推理从 d 点起算"）→ 段间回拉。管道版重写时丢失了旧版 RTC 的
d 步丢弃补偿，是这轮往复的主因之一。

**修复（`_on_rtc_chunk`）**：

- `d_stale = round(latency × fps)`：观测过期步数；
- 臂部目标取第 **d+N 步**（=相对"现在"领先 N 步，目标步N 语义不变）；
- 夹爪滴灌同步跳过前 d 步过期序列（与臂部同一时间基准）；
- 状态栏显示 `目标步N(d=6+N)` 可直接观察补偿量。

单元验证：延迟 0.3s 时前瞻从 3 步（回拉态）恢复到 9 步；低延迟（d=1）与
chunk 不足时正确钳位；投影剥离/大幅反向放行回归不受影响。

---

### 10.8 夹爪"抓住即松手"与微开合：力矩闭锁（2026-08-17 第四轮）

**现象**：夹爪抓住物体（力矩升到 ~0.5Nm）后很快松手放下；且总伴随微小开合。

**根因（数据实测支撑）**：
- 角度约定（从训练数据反推）：**角度增大=闭合，减小=张开**；抓紧帧（力矩>0.3Nm）
  角度 ≈ -0.52，松开帧 ≈ -1.15；
- **绝对角度指令 × 物体差异**：模型输出的是演示物体在演示抓取深度的保持角，
  数据中持物角度跨度 [-0.90, -0.34] 达 0.56rad——真机物体稍不同，"保持角"
  就可能比当前接触角更张开；
- **flow-matching 持物分支摇摆**：训练仅 3.5 epoch，"持物"状态后的分支是
  继续搬运/放下，模型分不清早晚 → 采到"放下"分支输出张开 → 防抖 0.5s
  挡不住持续意图 → 松手；
- 微开合：保持值 ±0.05 抖动 > 原死区 0.04。

**修复（`_on_seq_grip_tick` 力矩闭锁 grasp-latch，普通/RTC/推理一次共用）**：

1. **非对称死区**：张开方向死区 0.10rad（闭合 0.04）——闭合微动无害
   （推不到位由力矩限制兜底），张开微动多为噪声；
2. **力矩闭锁（分级放行，v2）**：力矩 > 0.25Nm 判定持物并记住保持角，
   张开指令按**目标开度差**分两级——这是"既不抓住就松、也不夹着不放"的
   关键区分（v1 只用 1.2s 持续意图判据，真机出现"总是夹着不放"）：
   - 开度差 > **0.25rad**（目标远超保持角）= 模型明确要开到大开位
     → **立即放行**（真实放置几乎零延迟）；
   - 开度差 ≤ 0.25rad（保持角附近徘徊，正是摇摆形态）→ 冻结，
     持续 0.6s 仍坚持才放行（中等幅度后备）；
   - 保持角跟随实际下发位置（夹得更紧后以新接触角为基准）；
   - 力矩 < 0.08Nm 迟滞退出（放置完成自动恢复）；
3. **不放 inhibit 闭合**：闭锁只管张开方向，越夹越紧永远允许。

### 10.9 夹爪回退直控（2026-08-19，RTC 部分后由 10.10 取代）

尽管防抖（10.6）、力矩闭锁 v2/v3（10.8）在单元仿真中均通过，真机表现始终
不如预期（v1 抓住即松 → v2 夹着不放 → v3 仍出现夹住后迅速放开）——执行侧
滤波无法可靠区分"采样摇摆"与"真实放置"，多层滤波反而引入新的失效模式。
**决定：夹爪通道整体回退到最初的直控模式**（普通/RTC/推理一次统一）：
20Hz 滴灌逐值直发，无死区、无换向驻留、无力矩闭锁，仅保留量程钳位
[-π/2, π/60]。

**教训**：执行侧滤波（尤其依赖单帧阈值/时间驻留的）对 flow-matching 的
chunk 级摇摆无效，夹爪的根治仍在训练侧（lookahead 重训、增数据、3次采样
平均）。随后用户进一步定位出 RTC 往复的时序根源（见 10.10），RTC 部分
升级为终点覆盖+限速；**普通模式维持直发至今**。

### 10.10 RTC 夹爪 v4：终点覆盖 + 斜坡限速 + 力矩保护（2026-08-19，用户方案）

普通模式保持直控滴灌不变；**只改 RTC**。用户定位的往复根因（正确）：

```
第1轮 chunk: -60→-10 闭合中，执行到 -20 时第2轮到达
第2轮 chunk: 起点 -32（=第1轮请求时刻的过期观测！），终点 -5
直发执行:    -20 → 回拉 -32 → -5   ← 往复
```

**方案（`_on_rtc_grip_tick` 限速斜坡 + `_on_rtc_chunk` 只取窗口末值）**：

1. **终点覆盖（治反复）**：每段新 chunk 不再重放序列，只取时滞补偿窗口的
   末值作为目标；斜坡恒从**上次实际下发位置**推进 → 永不回绕
   （-20 → 直接 -5；若新段反向则直接 -20 → -60）；
2. **限速（治力矩超调，学习手柄 xbox_control 的 D-pad 夹爪策略）**：
   闭合 1.0 rad/s、张开 1.5 rad/s（每 50ms tick 最多 0.05/0.075 rad）；
   闭合过快会让力矩瞬间冲过 0.5Nm 上限 → 力矩观测突变 → 模型分布外；
3. **力矩保护（同手柄三段式）**：软阈值 0.6×上限起预减速（推进量线性
   衰减）→ ≥上限锁定保位 → 保持意图不解锁（不反复撞击）；模型坚持更紧
   （目标 > 已到位+0.02rad）解锁重试（力矩仍高则零推进再锁）；张开方向
   永不被闭合锁定阻塞（放置正常）。

单元验证 6 场景 + ACT 集成回归全过：单调无回绕、触限零推进、保持不撞击、
放置正常、解锁重试、单步 ≤0.05rad。

**注意（遗留观察点）**：下发指令死区钳位 [-π/2, π/60]，而数据录到的反馈角
低至 -1.84——若发现"张不开到演示的开度"，需核对 L7 反馈角与指令角 的
offset/direction 映射（`_joint_offsets`/`_joint_directions`）。

## 十一、三种执行模式对比与选型（最终态）

| | 普通模式（顺序块） | RTC（管道平滑块） | 推理一次 |
|---|---|---|---|
| 执行机构 | 每段一次 MoveJ（S 曲线，段末归零速） | 每段 servo 线性插值，段间位置连续 | 一次 MoveJ 到端点 |
| 推理节奏 | 执行完再推理（段间微停 ~50ms） | 执行中提前推理（无停顿） | 手动单次 |
| 平滑性 | 高 | 高（均值+EMA+往复抑制） | 高 |
| 诊断日志 | 无 | 无 | 全量（`inference_once_logs/`） |
| 适用 | ACT（确定性输出）首选、精度优先 | SmolVLA（采样噪声大）首选、连续作业 | 故障诊断 |

### 参数整定速查

| 参数（界面/代码） | 默认 | 作用 |
|---|---|---|
| 步长mm | 8 | 段速度上限 = 步长×20（0.16m/s）；调大更快 |
| 姿态rad | 0.05 | 段姿态变化上限 = ×10（0.5rad/段） |
| 平滑α | 0.8 | 段端点 EMA；调小更平滑但更慢，调大更跟手 |
| 目标步N | 10 | 段目标取 chunk 第 N 步，窗口固定 0.5s；14~20 ≈ 1.4~2 倍速 |
| 低通滤波 | 开 | EMA 总开关；关闭=最快但采样噪声直出 |
| 3次采样平均 | 关 | 模型侧降噪（-30% 摆动）；SmolVLA 延迟 ×3 ≈ 0.9s 会撑破 0.5s 窗口造成停顿，RTC 下慎用 |
| `_rtc_deadband` | 6mm | 方向基准更新的最小位移（噪声死区） |
| `_rtc_genuine_rev` | 40mm | 位置真实反向阈值（大于则放行，如撤退） |
| `_rtc_genuine_rev_rot` | 0.25rad | 姿态真实反向阈值 |
| `_grip_deadband` | 0.04rad | 夹爪指令死区（小于则跳过） |
| `_grip_rev_dwell` | 0.5s | 夹爪换向最小驻留时间（防抖） |
| `_seq_max_jump` / `_seq_max_rot` | 0.10m / 0.6rad | 顺序块每段安全限幅 |
