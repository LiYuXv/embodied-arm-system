#### class RobstrideCanDriver

> Robstride 电机 Socket CAN 底层驱动（Linux 专用）

**后端类型**: `socketcan`

**连接方式**: Linux Socket CAN (`socket.socket(AF_CAN, SOCK_RAW)`)

**适用平台**: Linux（需要 Socket CAN 支持，如 can0、can1 等）

**使用条件**:
- 操作系统: Linux
- CAN 接口: 使用 Socket CAN（通过 `ip link` 命令创建）
- 示例: `can_name="can0"`

**特点**:
- 直接使用 Linux Kernel CAN 接口
- 延迟最低，性能最高
- 需要 root 权限或适当的 CAN 接口权限

```python
def compute_gravity(self, q: List[float]) -> List[float]:
    """
    计算重力补偿力矩: RNEA(q, v=0, a=0)

    物理意义: 当关节速度 v=0、加速度 a=0 时，
    RNEA 计算的力矩 tau 仅包含重力项 g(q)

    tau = M(q)*0 + C(q,0)*0 + g(q) = g(q)
    """
    q_pin = self._to_pinocchio_q(q)    # 转换关节角到Pinocchio配置向量
    v = np.zeros(self._model.nv)        # 零速度
    a = np.zeros(self._model.nv)        # 零加速度
    tau = pin.rnea(self._model, self._data, q_pin, v, a)
    return [float(tau[i]) for i in range(self._model.nv)]
```

### 2. 数学原理

**RNEA 完整公式:**
```
tau = M(q) * a + C(q, v) * v + g(q)
```

其中:
- `M(q)`: 质量矩阵 (惯性矩阵)
- `C(q, v)`: 科氏力/离心力矩阵
- `g(q)`: 重力向量
- `q`: 关节位置
- `v`: 关节速度
- `a`: 关节加速度

**重力补偿时:**
```
令 v = 0, a = 0
tau_gravity = M(q)*0 + C(q,0)*0 + g(q) = g(q)
```

## Pinocchio 运动学/动力学模块详解

### 模块: `kinematics.py`

基于 **Pinocchio** 库实现，独立于 ROS，CAN 和 ROS 模式共用。

#### 核心功能

| 功能 | 方法 | Pinocchio API | 数学描述 |
|------|------|---------------|----------|
| 正运动学 | `forward_kinematics()` | `pin.forwardKinematics()` | q → SE3 位姿 |
| 逆运动学 | `inverse_kinematics()` | DLS 迭代 | SE3 → q (数值解) |
| 雅可比 | `compute_jacobian()` | `pin.computeFrameJacobian()` | J = ∂X/∂q |
| 重力补偿 | `compute_gravity()` | `pin.rnea(q, 0, 0)` | τ = g(q) |
| 逆动力学 | `inverse_dynamics()` | `pin.rnea(q, v, a)` | τ = M·a + C·v + g |
| 正动力学 | `forward_dynamics()` | `pin.aba(q, v, τ)` | a = M⁻¹(τ - C·v - g) |
| 质量矩阵 | `mass_matrix()` | `pin.crba(q)` | M(q) |
| 科氏力矩阵 | `coriolis_matrix()` | `pin.computeCoriolisMatrix()` | C(q, v) |

#### 逆运动学算法 (ik_step)

实时控制循环专用，特点:
1. **SE3 对数映射**: 计算精确位姿误差，不受欧拉角奇异影响
2. **SVD 自适应阻尼**: 奇异区自动增大阻尼防止抖动
3. **Q5 奇异规避**: 当 q5 ≈ 0 时添加梯度项引导远离奇异
4. **步长限制**: `max_step` 限制单步关节增量

```python
# 核心迭代步骤
for iteration in range(max_iter):
    # 1. 前向运动学
    pin.forwardKinematics(model, data, q)
    
    # 2. 计算 SE3 误差
    err_se3 = oMf.actInv(target_se3)
    err = pin.log6(err_se3).vector  # 6维误差向量
    
    # 3. 计算 Jacobian
    J = pin.computeFrameJacobian(model, data, q, frame_id, pin.LOCAL)
    
    # 4. SVD 分析，自适应阻尼
    sigma = np.linalg.svd(J, compute_uv=False)
    s_min, s_max = sigma[-1], sigma[0]
    lam = damping  # 基础阻尼
    if s_min < threshold:
        lam = max(lam, damping + 0.08 * (1 - r))  # 增大阻尼
    
    # 5. 求解关节增量
    JtJ = J.T @ J + lam * I
    dq = np.linalg.solve(JtJ, J.T @ err)
    
    # 6. 积分更新
    q = pin.integrate(model, q, dq * dt)
```

## CAN 驱动后端选择 (slcan vs socketcan)

### 1. 两种驱动对比

| 对比项 | `RobstrideCanDriver` | `SlcanCanDriver` |
|--------|---------------------|------------------|
| 后端类型 | socketcan | slcan |
| 底层协议 | Linux Socket CAN | 串口 + SLCAN |
| 适用平台 | **Linux 专用** | Windows / Linux / macOS |
| 性能 | 更高（低延迟） | 稍低 |
| 硬件依赖 | Socket CAN 接口 | USB-CAN 适配器 |
| 权限要求 | root 或 can 组 | 串口权限 |
| 依赖库 | 标准库 | pyserial |

### 2. 选择条件

**选择 `socketcan` (RobstrideCanDriver)**:
- 操作系统: Linux
- CAN 接口: 使用 Socket CAN（如 can0、can1）
- 示例硬件: PCAN-USB, Vector, Socket CAN 接口卡

**选择 `slcan` (SlcanCanDriver)**:
- 操作系统: Windows、macOS、或 Linux（无 Socket CAN）
- 硬件: USB-CAN 适配器（LAWICEL、Seeed Studio CAN-BUS Shield V2 等）
- 需要通过串口连接

### 3. 使用示例

```python
from el_a3_sdk import ELA3Interface

# Linux + Socket CAN (默认，推荐)
arm = ELA3Interface(
    can_name="can0",
    backend="socketcan"  # 默认值
)

# Windows
arm = ELA3Interface(
    serial_port="COM3",
    backend="slcan",
    serial_baudrate=2000000,
    can_bitrate=1000000
)

# macOS / Linux 无 Socket CAN
arm = ELA3Interface(
    serial_port="/dev/tty.usbserial-xxxx",
    backend="slcan",
    serial_baudrate=2000000,
    can_bitrate=1000000
)
```

### 4. 底层实现

- **RobstrideCanDriver**: 使用 Linux `socket(AF_CAN, SOCK_RAW)` 直接与内核 CAN 驱动交互
- **SlcanCanDriver**: 通过串口发送 SLCAN 协议命令，由 USB-CAN 适配器转换为 CAN 信号

## 三、控制循环中的模式切换

### 3.1 控制循环主流程

```
_control_loop_main() @ 200Hz
        ↓
判断状态：
    ├─ RUNNING / ZERO_TORQUE → 执行 _control_loop_tick()
    └─ 其他状态 → 跳过
        ↓
_control_loop_tick(dt)
        ↓
1. 处理轨迹队列（如果有）
2. 获取 target_positions（_target_positions 缓存）
3. 判断 first_cmd：
   - True → 初始化 _last_cmd_positions 和 _gravity_input_positions
4. 计算重力补偿：
   - zero_torque=True → 使用反馈位置
   - zero_torque=False → 使用 target_positions
5. 遍历各关节：
   ├─ zero_torque=True → Kp=0, Kd=自适应/固定, 目标位置=当前反馈位置
   │                     （拖动时目标跟随，无恢复力）
   │
   └─ zero_torque=False → Kp>0, Kd>0, 目标位置=_target_positions
                        （拖动时产生恢复力，回到目标位置）
                        力矩 = Kp*(当前位置-目标位置) + Kd*(速度-0) + 重力补偿
```

### 3.2 零力矩模式 vs 关节空间阻抗模式

| 特性 | 零重力矩模式 | 关节空间阻抗模式 |
|------|-------------|----------------|
| Kp | 0 | >0（位置刚度） |
| Kd | 小（自适应） | 正常（速度阻尼） |
| 目标位置 | 跟随当前反馈位置 | 固定在当前位置 |
| 拖动行为 | 自由拖动，无恢复力 | 有恢复力，像弹簧 |
| 重力补偿 | 基于实际位置 | 基于目标位置 |
| 力矩公式 | Kd*(速度) + 重力补偿 | Kp*(位置误差) + Kd*(速度) + 重力补偿 |

## 六、注意事项

1. **控制循环必须运行**：修改后关闭零重力矩时，控制循环继续运行提供阻抗控制。如果控制循环未运行，需要确保 `_do_zero_torque_gravity` 在开启时已启动控制循环或后台线程。

2. **重力补偿精度**：关节空间阻抗模式下，重力补偿基于 `_target_positions`（固定目标位置），而非实时反馈位置。由于目标位置接近当前位置，误差很小。

3. **电机模式一致性**：修改后关闭零力矩时，如果电机已在运控模式，不会重新 disable/enable，避免力矩中断。

4. **夹爪处理**：夹爪（第7轴）始终使用 PP 模式（位置点动），不受零力矩模式影响。

## 程序关闭安全处理流程

### 修改文件
- `debugger/main_window.py` — `closeEvent()` 和 `_cleanup_before_close()`

### 原有问题

关闭窗口时机械臂无法安全退出，存在以下问题：

1. **没有急停（EmergencyStop）** — 关闭窗口时只发送 `disconnect`，如果机械臂在运动中或零力矩模式下，电机可能失控
2. **没有退出零力矩模式** — 如果处于零力矩模式直接断开，控制循环可能仍在发送运控帧
3. **命令队列异步执行，没有等待完成** — `submit_command` 只是将命令放入队列，不会等待执行完成，`worker.stop()` 可能在线程还没处理完命令时就结束了
4. **定时器未停止** — `monitoring_panel._timer` 继续运行，可能导致程序无法正常退出
5. **资源未释放** — 3D视图(plotter)、变量引用未清理，可能导致内存泄漏

### 修复后的关闭流程（12步安全清理）

### 代码实现

```python
def closeEvent(self, event):
    self._append_log(tr("win.closing"))
    self._cleanup_before_close()
    super().closeEvent(event)

def _cleanup_before_close(self):
    """关闭程序前的安全清理：急停、退出零力矩、失能电机、断开连接、停止线程、释放资源"""
    self._append_log("正在安全清理资源...")

    # 1. 停止所有定时器，避免清理期间UI更新
    self._append_log("  1. 停止监控定时器...")
    if hasattr(self.monitoring_window, 'panel') and hasattr(self.monitoring_window.panel, '_timer'):
        self.monitoring_window.panel._timer.stop()

    # 2. 停止手柄控制线程
    self._append_log("  2. 停止手柄控制...")
    self.gamepad_panel.cleanup()

    # 3. 急停机械臂（最高优先级，立即停止所有电机输出）
    self._append_log("  3. 执行急停...")
    if self.worker.is_connected and self.worker.is_enabled:
        self.worker.submit_command("emergency_stop")
        import time
        time.sleep(0.1)

    # 4. 如果处于零力矩模式，先退出零力矩模式
    self._append_log("  4. 退出零力矩模式...")
    if self.worker.is_connected:
        self.worker.submit_command("zero_torque_gravity", False)
        self.worker.submit_command("zero_torque", False)
        import time
        time.sleep(0.1)

    # 5. 取消任何正在进行的运动
    self._append_log("  5. 取消运动...")
    if self.worker.is_connected:
        self.worker.submit_command("cancel_motion")
        import time
        time.sleep(0.05)

    # 6. 失能电机
    self._append_log("  6. 失能电机...")
    if self.worker.is_connected and self.worker.is_enabled:
        self.worker.submit_command("disable")
        import time
        time.sleep(0.1)

    # 7. 断开连接（关闭CAN/串口）
    self._append_log("  7. 断开连接...")
    if self.worker.is_connected:
        self.worker.submit_command("disconnect")
        import time
        time.sleep(0.1)

    # 8. 停止后台工作线程
    self._append_log("  8. 停止后台线程...")
    self.worker.stop()

    # 9. 关闭监控窗口
    self._append_log("  9. 关闭监控窗口...")
    if self.monitoring_window.isVisible():
        self.monitoring_window.close()

    # 10. 释放3D视图资源
    self._append_log("  10. 释放3D视图...")
    if hasattr(self.viewer_3d, '_plotter') and self.viewer_3d._plotter:
        try:
            self.viewer_3d._plotter.close()
            self.viewer_3d._plotter = None
        except Exception:
            pass

    # 11. 清理变量引用，释放内存
    self._append_log("  11. 清理变量...")
    self._last_joint_states = None
    self._last_effort_states = None
    self._last_velocity_states = None
    self._last_end_pose = None
    self._last_status = None
    self._last_motor_feedback = None

    # 12. 强制垃圾回收
    import gc
    gc.collect()

    self._append_log("已安全清理资源")
```

### 安全设计原则

1. **优先级排序**：急停 > 退出零力矩 > 取消运动 > 失能 > 断开连接 > 释放资源
2. **防御式检查**：每个步骤都检查 `worker.is_connected` 和 `worker.is_enabled`，避免对已断开连接发送命令
3. **等待时间**：关键步骤后 `time.sleep()` 给后台线程执行命令的时间（50ms~100ms）
4. **异常保护**：3D视图释放使用 try/except，避免清理失败导致程序卡住
5. **内存释放**：清理所有状态变量引用，调用 `gc.collect()` 强制垃圾回收

## 10. [示教回放卡顿修复记录](#示教回放卡顿修复记录)

### 问题现象

示教界面录制轨迹后点击"回放"，机械臂一跳一跳运动，非常卡顿。

### 问题分析

**根本原因：采样率不匹配**

| 环节 | 频率 | 周期 |
|------|------|------|
| 录制 | 10 Hz | 100 ms |
| 控制循环 | 200 Hz | 5 ms |

控制循环每 5ms 执行一次，但轨迹点只有每 100ms 一个。在 `interface.py:383-385`：

```python
while (self._traj_index < len(self._trajectory) - 1 and
       self._trajectory[self._traj_index + 1].time <= elapsed):
    self._traj_index += 1
```

这意味着：
- 前 20 个周期 (0-100ms)：`_traj_index = 0`，目标位置不变
- 第 20 个周期 (100ms)：跳到 `_traj_index = 1`，目标位置突变
- 机械臂在 100ms 内一直跟踪同一个点，然后突然跳到新点 → **卡顿/跳跃**

### 修复过程

**阶段 1：改为推入控制循环队列**

- 原始实现：循环调用 `MoveJ(duration=0.1s)`，每个点单独 S-curve 规划
- 问题：`duration=0.1s` 太短，S-curve 刚加速就结束，机械臂只抖动
- 修复：新增 `trajectory_playback_requested` 信号，一次性推入控制循环队列

**阶段 2：线性插值到 200Hz**

- 问题：10Hz 录制点太稀疏，控制循环 20 个周期才更新一次目标
- 修复：在 `teaching_panel.py:_playback()` 中对录制轨迹做线性插值

```python
control_dt = 0.005  # 200Hz

for 每对相邻录制点 (pt0, pt1):
    dt_segment = pt1.timestamp - pt0.timestamp  # ~0.1s
    n_steps = int(round(dt_segment / control_dt))  # 20 步

    for k in range(n_steps):
        t = pt0.timestamp + k * control_dt
        alpha = k / n_steps

        # 线性插值位置
        pos = pt0.positions + alpha * (pt1.positions - pt0.positions)

        # 估算速度前馈（位置差分 / 时间差）
        vel = (pt1.positions - pt0.positions) / dt_segment
```

### 核心思路

```
录制 (10Hz) → 线性插值 (200Hz) → 控制循环队列 → 200Hz Kp跟踪
```

控制循环每 5ms 从轨迹队列取目标位置 + 速度前馈，通过 `send_motion_control(Kp=80, Kd=4, velocity_ff, gravity_torque)` 发送运控帧，电机平滑跟踪。
