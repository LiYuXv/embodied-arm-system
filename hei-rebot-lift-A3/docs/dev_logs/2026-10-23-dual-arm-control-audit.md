# 双臂控制程序审查（2026-10-23）

## 范围与已有功能

仅审查 `debugger/backend/arm_worker.py`、`debugger/main_window.py`、示教/标定面板及 `el_a3_sdk` 相关接口。未连接机械臂，未启动上位机真机控制。

- worker 为两臂分别创建 SDK 实例，臂1/臂2连接失败互不阻止；使能前分别检查七关节反馈新鲜度与角度范围。
- 两臂关节、力矩、电机反馈分别由信号送往主窗口；关节控制、双臂 MoveJ、示教轨迹回放按各臂连接/使能状态分发。
- 示教面板可选择普通零力矩或带重力补偿零力矩；SDK 退出零力矩时同步当前位置，并恢复夹爪 PP 模式。
- 标定面板按臂选择、采样及保存 `inertia_params_arm1.yaml` / `inertia_params_arm2.yaml`；连接时各臂优先加载各自文件，否则回退到共用 `inertia_params.yaml`。SDK 仅在 YAML 的 `use_calibrated_params` 为真时应用惯性参数。标定设置面板展示/编辑共用参数文件，其独立启动按钮当前禁用。
- 主窗口关闭/安全退出会提交急停和断开命令，再停止 worker。

## 确认的问题与修复

1. **仅臂2连接时反馈轮询访问空臂1。** `_poll_feedback()` 已发出臂2信号后仍调用 `self.arm.GetArmJointMsgs()`，异常被吞掉并提前返回。现在无臂1时结束本次臂1轮询，臂2反馈仍正常送达。
2. **SDK 使能返回 `False` 时仍标记该臂已使能。** SDK 可在部分电机失败后返回 `False` 或抛出异常。现在该臂尝试失能，保持未使能标志并报告失败；另一臂仍可独立使能。失能失败另报错，要求现场执行急停。
3. **示教零力矩模式进入/退出接口可能不配对。** 活动期间改变重力补偿勾选会使退出调用另一种模式的关闭接口。现在进入时锁定选择并记录实际模式，退出调用对应接口。
4. **未使能的臂也会收到零力矩切换请求。** 现在 worker 按臂使能状态过滤，并检查 SDK 返回值。SDK 带重力补偿模式在底层零力矩进入失败时不再启动重力线程。
5. **停止线程可能跳过排队的急停/断开。** 原 `stop()` 立即清除运行标志后只等待三秒，worker 若刚结束一次循环可能不再处理队列。现在清掉尚未执行的普通命令，由 worker 依次执行急停、断开、停止标记并等待线程退出。
6. **一臂急停或断开抛异常会跳过另一臂。** 现在逐臂尝试，单臂失败单独报告，成功臂的状态分别更新。

## 安全问题复核（2026-10-23）

- `stop()` 现在以 3000 ms 有界等待。超时会报告工作线程仍可能运行；主窗口拒绝关闭并保留 worker 对象。`_on_safe_exit()` 也只在停机确认后报告完成。Python 命令队列无法中断正在阻塞的 SDK/CAN 调用，超时必须依靠现场急停和通信排查；未采用 `terminate()`。
- 关停标志和入队操作由同一队列锁保护。关停开始时清除待执行命令，按急停、断开、shutdown 顺序执行；迟到命令被拒绝，处理到 shutdown 即退出队列循环，也不再进行反馈轮询。
- `_do_disconnect()` 检查逐臂 `DisableArm()` 返回值。返回 `False` 时报告失能失败、保持该臂连接及使能状态、不调用该臂 `DisconnectPort()`，同时继续处理另一臂。SDK 的 `DisconnectPort()` 内部再次调用 `DisableArm()`，但忽略其返回值，所以不能把端口断开当成失能成功。
- 离线测试新增 5 项，合计 13 项通过，覆盖停机超时、并发迟到运动命令、shutdown 后残留命令、单臂失能失败与另一臂继续断开、窗口拒绝关闭。原有 8 项继续通过。静态编译和 `git diff --check` 通过。测试未加载 Qt 或连接硬件。

真机仍需在有安全支撑和现场急停的条件下确认：SDK/CAN 阻塞时 GUI 的超时报警与后续恢复、运动中急停和双臂断开顺序、单臂失能返回失败时实际电机状态与重试流程。

## 最后边界复核（2026-10-23）

- 用实际 `_do_enable()` / `_do_disconnect()` 方法的 AST 与假 SDK 重现：臂1部分使能失败，随后的回滚失能也失败时，worker 的 `_enabled=False` 仍可能对应未失能电机。此前断开流程根据此标志跳过显式失能检查；SDK `DisconnectPort()` 虽再次调用 `DisableArm()`，但忽略其失败值，造成错误的安全断开宣告。
- 现在每个非空 SDK 臂在断开前都显式检查 `DisableArm()`，不依赖 worker 使能标志。返回 `False` 或抛异常时，保留该臂 SDK 实例与连接标志，逐臂报告「未确认电机安全失能」，仍处理另一臂；只有全部断开才输出「已断开连接」。急停将 worker 标志置为未使能时同样适用。
- 主窗口先让 worker 拒收新命令、清除待执行普通命令，再停止 Joy-Con、VR 和 VLA 控制源，最后排入安全序列。三个控制源分别清理；其中一个抛异常时仍尝试其余来源，执行急停但保留连接、不排入断开，并报告停机未确认。手柄断连信号在停机期间不会自动恢复 VLA 控制。保留原先的窗口拒绝关闭、独立错误日志及安全退出失败提示。
- 离线测试增至 18 项，新增部分使能与回滚失能均失败、worker 标志为未使能时仍拒绝断开该臂并处理另一臂，以及运动源清理阶段拒收命令、清理异常不跳过其他来源且保留连接、停机期间不恢复 VLA。`python3 scripts/tests/test_dual_arm_control_offline.py -v`、指定文件 `py_compile`、`git diff --check` 均通过。未运行 Qt 真机窗口或 CAN 操作。
- 仍需现场验证直接调用 SDK 的运动源在清理时是否能及时退出，以及底层 SDK/CAN 调用已经阻塞时的急停响应；软件关停流程不能抢占正在执行的阻塞调用。
