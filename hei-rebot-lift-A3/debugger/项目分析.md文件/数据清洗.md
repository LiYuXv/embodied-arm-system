# 数据清洗与奖励标注（RECAP 自动打分机制）

> 基于 π\*₀.₆ 论文（[arXiv:2511.14759](https://arxiv.org/abs/2511.14759)）的 RECAP 方法，
> 为本项目 SmolVLA + LeRobot v3.0 数据集设计的片段级奖励标注方案。

相关文件路径：`debugger/` 目录下

---

## 一、背景：RECAP 的自动打分机制

### 1.1 RECAP 是什么

RECAP（RL with Experience and Corrections via Advantage-conditioned Policies）是 Physical Intelligence 在 π\*₀.₆ 中提出的通用 RL 训练配方，让 VLA 模型能通过真实世界部署经验自我改进，突破模仿学习（IL）的性能上限。

模仿学习的两个根本缺陷：
1. **复合误差（Compounding Error）**：策略误差随时间累积
2. **性能上限受限**：最多只能达到示范数据的水平，无法超越人类遥操作的速度和鲁棒性

RECAP 通过 RL，利用**示范数据 + 自主经验 + 专家干预**三类异构数据，让策略"从经验中学习"。

### 1.2 自动打分的完整链路

RECAP 的"自动打分"由三个环节构成：

```
人类标注成功/失败
      ↓  （稀疏奖励）
分布式价值函数预测"到成功的剩余步数"
      ↓  （n-step 优势估计）
二值化改进指标 I_t（这步动作比平均好还是差）
      ↓  （优势条件化）
条件化策略学习（good 动作多学，bad 动作少学）
```

#### ① 奖励函数设计（极简稀疏奖励）

RECAP 用一个适用于任何任务的稀疏奖励（论文 Eq. 5）：

```
r_t = | 0           如果 t=T 且成功
      | -C_fail     如果 t=T 且失败    （C_fail 是大负常数）
      | -1          其他（每步）
```

价值函数对应"（负的）到成功完成的剩余步数"，**同时编码了"能否成功"和"多快成功"两个维度**。
预测值归一化到 (-1, 0)，按任务最大 episode 长度归一化。

#### ② 分布式价值函数（Critic）

- 架构与 VLA 策略相同，但用更小的 VLM backbone（π\*₀.₆ 用 670M，基于 Gemma 3）
- 输出在 B=201 个离散化价值 bin 上的概率分布 p_φ(V | o_t, ℓ)
- 用蒙特卡洛回报 + 交叉熵损失训练（论文 Eq. 1）
- 简单可靠，适合大规模 VLA（比离策略 Q-learning 稳定）

#### ③ 优势估计与二值化改进指标

从价值函数计算 n-step 优势（附录 A-F）：

```
后训练:  A(o_t, a_t) = Σ_{t'=t}^{t+N-1} r_t' + V(o_{t+N}) - V(o_t)    （N=50 前瞻）
预训练:  A(o_t, a_t) = Σ_{t'=0}^{T} r_t' - V(o_t)                       （N=T，单次推理）
```

二值化为改进指标（论文核心工程选择——用阈值 ε_ℓ 而非 CFG 的 β）：

```
I_t = 𝟙( A(o_t, a_t, ℓ) > ε_ℓ )
```

ε_ℓ 设为使约 30%（预训练）/ 40%（后训练）的数据优势为正。

### 1.3 核心创新：优势条件策略提取（Policy Extraction）

RECAP 不用 PPO/策略梯度（flow matching 模型无易处理 log-likelihood，难扩展），也不用 AWR（丢弃大量数据，策略变慢），而是用**优势条件（Advantage Conditioning）**：

让策略以"这个动作有多好"（I_t）作为额外输入条件。基于 CFGRL [Frans2025] 的理论推导：

```
π̂(a|o,ℓ) ∝ πref(a|o,ℓ) · ( πref(a|I,o,ℓ) / πref(a|o,ℓ) )^β
```

当 β=1 时，**π̂(a|o,ℓ) = πref(a|I,o,ℓ)**——直接从"以改进指标为条件"的策略采样。

训练目标（论文 Eq. 3）：

```python
min_θ  E_{D_πref} [
    -log π_θ(a_t | o_t, ℓ)                    # 无条件（正则化）
    -α · log π_θ(a_t | I_t, o_t, ℓ)           # 有条件（改进）
]
```

- 数据集 D_πref 包含**所有收集到的数据**（示范 + 自主 + 纠正）
- **专家纠正动作强制 I_t = True**
- 训练时随机 dropout I_t（30%），支持推理时 CFG（β>1）

在 π\*₀.₆ 中的实现：优势指标作为**文本输入**加入（`"Advantage: positive/negative"`），
位置在子任务预测之后、动作之前——只影响动作 log-likelihood。

### 1.4 实验效果

| 任务 | RECAP vs IL | 关键提升 |
|------|------------|---------|
| 多样化衣物折叠 | 吞吐量 ×2+ | 失败率减半 |
| 制作浓缩咖啡 | 吞吐量 ×2+ | 连续运行 13 小时 |
| 盒子组装 | 成功率 ~90% | 4 阶段全提升 |
| T 恤折叠 | 成功率 >90% | 失败模式移除达 97% |

优势条件 vs AWR/PPO：RECAP 远超其他方法；AWR 策略变慢；PPO 离线下需极小信任域，性能差。

## 二、本项目的标注方案设计

### 2.1 标注粒度选择

采用 **片段级区间标注**（介于 episode 级和每步级之间）：

- 比每步密集奖励省力（无需逐帧标）
- 比 episode 级二值标签更精细（能区分同一 episode 内的好/坏操作段）
- 标注后由价值函数自动扩展到未标注帧

### 2.2 标签定义与 RECAP 映射

| 标注标签 | 含义 | RECAP 映射 | advantage_indicator 值 |
|---------|------|-----------|----------------------|
| `good` | 好的操作/正确动作 | I_t = True（正优势） | `1` |
| `bad` | 错误操作/失败动作 | I_t = False（负优势） | `-1` |
| `neutral` | 中性/可接受但不理想 | 由价值函数推断 | `0` |
| 未标注 | — | 由价值函数推断 | `0` |

### 2.3 存储格式

标注文件位置：`lerobot_data/<dataset>/meta/reward_annotations.json`（与 LeRobot 元数据并列，不破坏原数据）

```json
{
    "version": "1.0",
    "label_type": "fragment_interval",
    "labels": {
        "good":    {"color": "#2ecc71", "advantage": 1,  "desc": "好的操作/正确动作"},
        "bad":     {"color": "#e74c3c", "advantage": -1, "desc": "错误操作/失败动作"},
        "neutral": {"color": "#f39c12", "advantage": 0,  "desc": "中性/可接受但不理想"}
    },
    "episodes": {
        "0": [
            {"start": 10, "end": 50, "label": "good", "note": "抓取成功"},
            {"start": 60, "end": 90, "label": "bad",  "note": "掉落物体"}
        ],
        "1": [...]
    }
}
```

`start`/`end` 为 episode 内的帧索引（与 parquet 的 `frame_index` 列对齐）。

## 三、工具文件说明

以下三个文件均位于 `debugger/` 目录：

| 文件 | 作用 |
|------|------|
| `annotation_store.py` | 标注存储模块（JSON 读写、区间增删、统计） |
| `label_rewards_qt.py` | 标注 GUI 工具（双摄回放 + 区间标记 + 时间轴可视化） |
| `expand_annotations.py` | 区间 → 逐帧 `advantage_indicator` 列展开脚本 |

### 3.1 annotation_store.py

`AnnotationStore` 类负责单个 LeRobot 数据集的奖励标注读写：
- `load()` / `save()`：JSON 持久化（写入时用 tmp + replace 保证原子性）
- `add_interval(ep, start, end, label, note)`：添加区间，自动按 start 排序
- `remove_interval(ep, index)` / `update_interval(...)` / `clear_episode(ep)`
- `stats()`：返回各标签帧数与区间总数统计

### 3.2 label_rewards_qt.py（标注 GUI）

复用 `visualize_data_qt.py` 的 `OfflineDataset` 类做视频帧加载，主要组件：
- `PlaybackThread`：顺序回放线程，发出帧索引信号
- `TimelineWidget`：时间轴可视化（彩色色带显示已标注区间 + 当前位置 + 待确认区间）
- `LabelingWindow`：主窗口

### 3.3 expand_annotations.py

将 `reward_annotations.json` 中的区间展开为逐帧列：
- 读取全部 parquet 的 `episode_index` / `frame_index` / `index` 列
- 按区间填充 `advantage_indicator`（int8）
- 注入列到每个 parquet 文件
- 更新 `meta/info.json` 的 features 注册新特征

两种模式：
- `--mode copy`（默认，安全）：复制数据集到 `<name>_annotated`，在副本上操作
- `--mode inject`：直接修改原 parquet 文件

## 四、使用流程

### 第 1 步：标注数据

```bash
cd debugger
python3 label_rewards_qt.py --root ./lerobot_data --dataset ela3_demo2
```

GUI 操作说明：
1. 顶部下拉框选择**数据集**和 **Episode**
2. 双摄（cam1/cam2）自动同步回放
3. 标注区间：
   - 看到好操作：按 `[` 设起点 → 拨到结束位置按 `]` → 选 `good` → 按 `Enter` 添加
   - 看到错操作：同上流程，选 `bad`
4. 整 episode 成功/失败可一键"全部=好/坏"
5. `Ctrl+S` 保存到 `meta/reward_annotations.json`

**快捷键速查：**

| 快捷键 | 功能 |
|--------|------|
| `Space` | 播放/暂停 |
| `←` / `→` | 后退/前进一帧 |
| `G` / `B` / `N` | 设当前标签为 good/bad/neutral |
| `[` | 标记区间起点 |
| `]` | 标记区间终点 |
| `Enter` | 添加区间（用当前 start/end + 标签） |
| `Ctrl+S` | 保存标注 |
| `Ctrl+Z` | 撤销最后一个区间 |
| `Ctrl+D` | 删除选中区间 |

时间轴会以彩色色带显示已标注区间（绿=good，红=bad，橙=neutral），白色半透明带显示待确认区间。

## 五、与 RECAP 训练的衔接规划

当前阶段的标注对应 RECAP 的 `I_t`（改进指标）。后续做 RECAP 式训练时（待标完足够数据后展开），SmolVLA 需要的改造：

### 5.1 近期：SFT + 优势条件（轻量改造）

最简单的衔接方式——参考 RECAP 的"SFT 阶段"做法：

1. 对所有 `advantage_indicator=1`（good）的帧，相当于高质量示范，正常 SFT
2. 对 `advantage_indicator=-1`（bad）的帧，降权或过滤（类似 filtered BC）
3. 这已经能带来超过纯 IL 的效果（RECAP 论文 Fig. 7 中 offline RL + SFT 基线）

SmolVLA 输入侧的改造：将 `advantage_indicator` 编码为文本前缀注入 prompt：
```
任务: "put the bear in the box"
优势: "positive"   ← advantage_indicator=1 时
```

### 5.2 中期：训练价值函数（Critic）

用 episode 级成功标签（从区间标注派生：episode 内 good 帧占比 > 阈值 = 成功）训练一个 critic：
- 输入：观测 o_t + 语言指令 ℓ
- 输出：到成功的剩余步数（归一化到 -1~0）
- 架构：可复用 SmolVLA 的 VLM backbone（较小版本）+ 分布式输出头

### 5.3 远期：完整 RECAP 循环

```
预训练价值函数 + 优势条件策略
      ↓
SFT 微调（I_t ≡ True）
      ↓
自主 rollout 收集数据 + 专家干预纠正
      ↓
重训价值函数 → 计算 I_t → 重训策略   ← 可迭代
```

## 七、注意事项

1. **先备份再 inject**：`--mode inject` 会修改原始 parquet 文件，建议优先用 `--mode copy`
2. **标注质量 > 数量**：RECAP 论文显示，精准标注关键失败片段比大量模糊标注更有效（失败模式移除实验仅需 600 条轨迹达 97% 成功率）
3. **相机对齐**：标注时 `start`/`end` 是 episode 内帧索引，与 parquet `frame_index` 列对齐；若数据集经过裁剪（见 `数据问题分析.md`），需确保 frame_index 已规整
4. **多数据集**：每个数据集独立维护自己的 `reward_annotations.json`
5. **与现有训练的兼容**：`advantage_indicator` 注册为普通特征，不影响现有 SmolVLA/ACT 训练（不读取该列时自动忽略）

## 八、标注策略实践问答

### 8.1 采集时是否要默认标注 neutral？——不建议

`neutral` 与"未标注"展开后都是 `advantage_indicator=0`，均"留给价值函数推断"，训练侧**完全等价**。采集时自动写入全 episode neutral：

- 对训练**零信息增益**，与不写一样；
- **污染账本**：之后无法区分"人工复核过、判定平庸"与"从未复核"的片段。

采集时真正值得记录的是 **episode 级成功/失败**（RECAP 稀疏奖励 `r_T` 的来源，操作员只需一个按钮）：

| 采集时记录 | 映射 |
|-----------|------|
| 任务成功 | 整 episode = good（I_t=True） |
| 任务失败 | 整 episode = bad（r_T=-C_fail） |
| 不评 | 不写标注，留给价值函数推断 |

若遥操作中发生**专家干预纠正**，干预帧可直接记 `I_t=True`（RECAP 强制正优势），比事后回看更准。

### 8.2 一段 episode 内本来就有成功和失败的部分，怎么标？

混合质量 episode 正是 RECAP 要利用的数据形态（失败段 `I_t=False`，策略学着避开），**不要删失败段，标注它**。片段级标注策略：

| 片段类型 | 标注 | 说明 |
|---------|------|------|
| 明确失败段（掉落/碰撞/偏离目标/卡死挣扎） | `bad` | 框住失败发生区段即可；n-step 优势（前瞻 N≈50 帧）会自动把负优势**回传到失败前的因果帧**，无需精确追溯"从哪一帧开始走错" |
| 明确成功的关键推进段（成功抓取/放置） | `good` | 等价于正示范 |
| 失败后的**恢复段**（纠正、重试直至成功） | `good`（优先标） | 恢复行为是 RECAP 超越 IL 的最主要来源，最珍贵 |
| 静止/看不清/拿不准的段 | 不标 | 留 0 给价值函数推断；模糊标注比不标更伤 |

要点：

- **无需整段覆盖**，每个 episode 标 1~3 个关键区间即可；
- 当前数据规模（~36 episode）下，建议**所有失败段全标**（RECAP 论文失败模式移除实验仅用 600 条轨迹即达 97% 成功率）。

### 8.3 未标注的部分对模型训练有没有作用？——有，且是主体

- **纯 BC**（不读 advantage 列）：所有帧一视同仁被模仿，未标注帧占训练信号的**主体**。所以静止段必须先剪掉，否则模型会学到"站着不动"。
- **完整 RECAP**（训练了 critic）：未标注帧由价值函数推断优势并自动二值化 `I_t`——"稀疏人标 → 密集机标"，一帧不浪费。
- **简化方案**（§5.1 filtered BC + 优势条件）：good 正常/加强学，bad 降权或过滤，未标注帧**按普通权重正常学**，是策略学习任务流形的基础数据。

标注的作用不是"让数据生效"，而是"告诉模型哪些帧多学、哪些帧少学"。

### 8.4 操作顺序（重要，不能乱）

`reward_annotations.json` 以 `episode_index` 为键，而**剪辑/合并都会重排 episode_index**，之后旧标注全部错位。固定顺序：

```
采集 → 剪辑静止段 → 合并数据集 → RECAP 标注 → expand_annotations 展开 → 训练
```

可选提效手段：

- **录制时打粗标记**：录制程序加热键，失误瞬间记一个时间戳写入 `note`，回放时只在粗标记附近精修区间，省去全程回看；
- **录短 episode**：任务可分解时"一次尝试一个 episode"，episode 级 good/bad 即天然达到片段粒度，几乎无需逐段标注；代价是文件数变多、任务上下文变短。
