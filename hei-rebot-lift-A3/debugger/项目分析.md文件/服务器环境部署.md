# 服务器环境部署与训练指南（SmolVLA / pi0.5）

本文档说明如何在新的 GPU 服务器上从零部署训练环境，并启动 SmolVLA（smolvla_torque）
训练。pi0.5（pi05）全量微调的增量文件传输与启动见 §8；RECAP / RL（R2 加权 SFT +
R3 优势加权策略改进）的增量文件与补丁见 §9。补丁与 tokenizer 细节见
`TRAIN_README.md` 的 pi0.5 章节 §4。RECAP 数据准备链（sidecar / 组优势 / critic /
优势加权 R3 训练）的增量传输与启动见 §9。

已验证环境：
- 本机：Ubuntu / conda env `VLA` / Python 3.12 / torch 2.10.0+cu128 / lerobot 0.6.1 / RTX 4080 SUPER 16G
- 服务器：torch 2.7.0+cu128 / CUDA 12.8（其余依赖相同，自检全部通过）

## 1. 服务器要求

| 项目 | 要求 |
|---|---|
| 系统 | Ubuntu 20.04 / 22.04（其他 Linux 亦可） |
| GPU | NVIDIA 显卡，显存 ≥ 16 GB（720p 双摄 + batch 16）；≥ 24 GB 更稳妥 |
| 驱动 | 支持 CUDA 12.8 的 NVIDIA 驱动（`nvidia-smi` 可查） |
| 内存 | ≥ 32 GB（视频解码 + DataLoader 占内存大） |
| 磁盘 | ≥ 50 GB 剩余空间（依赖 ~10G + 预训练权重 ~8.3G + 数据集 1.4G + checkpoint 每个 1.5G） |

```bash
    pillow==12.2.0 \
    pyarrow==24.0.0 \
    pandas==3.0.3 \
    matplotlib==3.10.9 \
    gymnasium==1.3.0 \

    termcolor==3.3.0 \
    pyyaml==6.0.3 pyyaml-include==1.4.1 \
    wandb==0.24.2
```

> 说明：
> - `torchcodec` 版本须与 torch 大版本匹配：torch 2.10→`torchcodec==0.10`，2.9→`0.9`，2.8→`0.7`，**2.7→`0.5`**，2.6→`0.2`（官方兼容表）。若你装的是 torch 2.7，请把上面命令中的 `torchcodec==0.10.0` 改为 `torchcodec==0.5`。
> - `torchcodec` 还需要系统安装 **FFmpeg 共享库**：`apt-get install -y ffmpeg`（或 `conda install -c conda-forge ffmpeg`）。不装也可以——torchcodec 加载失败时 lerobot 会自动回退 pyav 解码后端（`av` 包自带解码库），训练不受影响。
> - 依赖也可以全部装进 base 环境（个人专用服务器），后续命令去掉 `conda run -n VLA`、直接用 `python` 即可。
> - `wandb` 可选（yaml 中 `wandb.enable: false`，不开可不装）。
> - `opencv-python-headless` 用 headless 版，服务器无显示环境也不会报错。
> - 不必安装本项目（`el_a3_sdk`）本身，训练只依赖 lerobot + 上述库。

## 7. 常见问题

| 问题 | 解决 |
|---|---|
| `torch.cuda.is_available() = False` | 先 `nvidia-smi`：**命令不可用** = 实例没分到 GPU（autodl 注意不要用「无卡模式」开机）；**驱动版本 < 570** = 带不动 cu128 版 torch，换装低 CUDA 版：`pip install torch==2.7.0 torchvision==0.22.0 --index-url https://download.pytorch.org/whl/cu124`（cu124 需驱动 ≥ 550） |
| torchcodec 加载失败（`libavutil.so.xx not found`） | 版本不匹配或缺 FFmpeg 库：torch 2.7 装 `pip install torchcodec==0.5` 并 `apt-get install -y ffmpeg`；**也可直接忽略**，lerobot 自动回退 pyav 解码后端，不影响训练 |
| `CUDA out of memory` | yaml 中 `batch_size` 16 → 8；`num_workers` 4 → 2 |
| `DataLoader worker ... Killed` | 系统内存不足：`pkill -9 -f train_model.py` 清残留进程；降 batch/workers |
| `No module named 'lerobot.policies.smolvla'` | 装错 lerobot 版本，必须 `lerobot==0.6.1` |
| 找不到数据集/预训练权重 | 确认按第 4 节目录结构放置，yaml 中是相对路径，必须在 `debugger/` 下运行 |
| HF datasets 缓存撑爆磁盘 | 删除 `~/.cache/huggingface/datasets/parquet`（下次加载自动重建） |
| `wandb` 报错 | yaml 里 `wandb.enable: false`，或先 `wandb login` |
| HF 请求空转重试（`Network is unreachable` / `Retrying in Ns`，启动卡数分钟） | 未设 `HF_HUB_OFFLINE=1`：transformers 对 tokenizer 可选文件（如 chat_template.jinja）做 HEAD 新鲜度检查，在无法访问 huggingface.co 的环境（无外网服务器 / 国内直连被墙）每个文件超时重试 5 次后才回退缓存。**不是重新下载**，缓存齐全时不影响结果，只是白等 10 分钟以上 | 命令前加 `HF_HUB_OFFLINE=1`，或改用 `train_model_pi05.py`（内置该变量）；也可 `echo 'export HF_HUB_OFFLINE=1' >> ~/.bashrc` 永久生效。⚠️ 不要用 hf-mirror 镜像替代——门控仓库 403 会直接抛异常 |

显存/内存更详细说明见 `TRAIN_README.md` 第 6 节。

`/root/autodl-tmp/debugger`（以下命令在**本机** `debugger/` 目录执行）：

| # | 文件/目录 | 大小 | 说明 |
|---|---|---|---|
| 1 | `train_model_pi05.py` | 2KB | pi05 专用入口（内置 `HF_HUB_OFFLINE=1` 等环境变量，默认加载 pi05_omy.yaml） |

> 本台服务器（seetacloud 6000 Pro）已确认：lerobot 0.6.1 装在 **base 环境**，
> 路径 `/root/miniconda3/lib/python3.12/site-packages/lerobot`。也可跳过中转、
> 本机一步直传覆盖：
> ```bash
> rsync -avz -e "$S" .../policies/pi_gemma.py \
>   $H:/root/miniconda3/lib/python3.12/site-packages/lerobot/policies/
> rsync -avz -e "$S" .../policies/pi05/modeling_pi05.py \
>   $H:/root/miniconda3/lib/python3.12/site-packages/lerobot/policies/pi05/
> ```
> （省略号为本机 VLA 环境的完整前缀 `/home/chen/anaconda3/envs/VLA/lib/python3.12/site-packages/lerobot`）

⚠️ 补丁覆盖**必须在服务器装好环境（§3，lerobot==0.6.1）之后执行**，否则
site-packages 路径不存在（rsync 报 `mkdir ... failed: No such file or directory`）。
服务器上自动定位 lerobot 安装路径并覆盖：

```bash
# ============ 以下在服务器执行 ============
# 自动定位 lerobot（VLA 环境优先，装进了 base 也能找到）
PYBIN=$(conda run -n VLA --no-capture-output which python 2>/dev/null || which python)
LEROBOT_DIR=$($PYBIN -c "import lerobot, os; print(os.path.dirname(lerobot.__file__))")
echo "$LEROBOT_DIR"    # 应输出 .../site-packages/lerobot；为空说明 lerobot 未安装，先回 §3
cp /root/patches/pi_gemma.py "$LEROBOT_DIR/policies/"
cp /root/patches/modeling_pi05.py "$LEROBOT_DIR/policies/pi05/"

# 验证补丁已生效（应输出 2 行匹配）
$PYBIN - <<'EOF'
import inspect, lerobot.policies.pi_gemma as g, lerobot.policies.pi05.modeling_pi05 as m
src = inspect.getsource(g)
print("pi_gemma 补丁:", "OK" if "inspect.signature(create_causal_mask)" in src else "缺失!")
src2 = inspect.getsource(m)
print("pi05 视觉键补丁:", "OK" if "vision_tower.vision_model." in src2 else "缺失!")
EOF
```

服务器侧按序验证并启动（**lerobot 装在 base 环境时，去掉所有
`conda run -n VLA --no-capture-output`，直接 `python ...`**）：

```bash

  "from transformers import AutoTokenizer; AutoTokenizer.from_pretrained('google/paligemma-3b-pt-224'); print('OK')"

# ③ 启动全量微调（tmux，SSH 断连不中断）
```

⚠️ 启动后**第一件事**检查权重加载日志：必须出现
`Remapped 812 state dict keys` + `All keys loaded successfully!`。
若刷出大量 `Missing keys`（437 个 vision_tower），说明第 5 步补丁未生效，
立即停训重打补丁——否则视觉塔为随机初始化，模型全盲。

- 全量微调每份 checkpoint 含优化器状态（约 20~35GB），`save_freq: 3000` 共 5 份
  + last，数据盘预留 ≥ 150GB，或定期删除旧编号目录只留 last。
- 显存峰值预计 60~65GB（bs=16），96GB 余量充足；时长以首小时 tqdm ETA 为准
  （粗略估计 10~16 小时）。
- 训完拉回本地部署：`rsync -avP -e "ssh -p 32044" \
  root@connect.westb.seetacloud.com:/root/autodl-tmp/debugger/ckpt/pi05_ela3_fullft/checkpoints/last/pretrained_model \
