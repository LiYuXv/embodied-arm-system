# EL-A3 机械臂硬件控制分析（电机模式 / 零力矩 / 夹爪）

> 分析对象：`el_a3_sdk/interface.py`（SDK 电机控制接口）、`debugger/widgets/teaching_panel.py`（示教/零力矩界面）、`demo/xbox_control.py`（手柄控制）。
> 问题背景：手柄控制 L7 夹爪正常顺滑；在示教界面开启再关闭零力矩模式后，L1-L6 恢复正常，但 L7 手柄控制变得非常不顺畅。
> 本文记录电机模式体系、零力矩模式的进入/退出机制、根因分析及已实施的修复（方案 A）。

---

## 1. 启动 → 连接 → 使能后，各关节处于什么模式

`EnableArm()`（interface.py:619）对 7 个电机是**两种模式**：

| 关节 | 运行模式 | 驱动方式 |
|---|---|---|
| L1~L6 | `RunMode.MOTION_CONTROL`（运控 Type 1） | 200Hz 控制循环发 PD 帧（kp=80/kd=4 + 速度前馈 + 重力补偿） |
| **L7 夹爪** | `RunMode.POSITION_PP`（interface.py:638 `is_gripper` 特判：`actual_mode = RunMode.POSITION_PP if is_gripper else run_mode`） | `set_position_pp()` 写 LOC_REF，**电机固件内部按 vel=6 rad/s、acc=15 rad/s² 规划平滑运动** |

- 控制循环在运动命令前自动启动（arm_worker.py:378 `_ensure_control_loop`，200Hz）。
- 手柄/VR/夹爪面板控制 L7 全部走 `GripperCtrl()` → `_target_gripper=角度`、`_gripper_dirty=True` → 控制循环 tick 尾部（interface.py:536-538）发 PP 指令。
- L7 在 PP 模式下**只响应 PP 指令**，每 tick 同时发出的 Type 1 帧被电机忽略——所以正常时手柄控制夹爪平滑。

## 2. 开启零力矩模式时发生了什么

教学面板（默认勾选重力补偿）流程：

```
teaching_panel._toggle_zero_torque (teaching_panel.py:149)
  └─ gravity 勾选 → zero_torque_gravity_requested.emit(True)
       └─ main_window (main_window.py:274) → worker "zero_torque_gravity" (arm_worker.py:520)
            └─ ZeroTorqueModeWithGravity(True, kd=[0.05,0.05,0.05,0.0125,0.0125,0.0125,0.05])
                 └─ 控制循环运行中 → ZeroTorqueMode(True, kd=0.05)  (interface.py:1034-1036)
```

`ZeroTorqueMode(True)`（interface.py:915-946）核心动作：

```
对 L1~L7 每个电机：disable → set_run_mode(MOTION_CONTROL) → enable
```

**关键：L7 被强制从 PP 模式切换到 MOTION_CONTROL 模式**（注释明确写明"以便 L7 也能被拖动"）。此后控制循环以 Kp=0 + 自适应 Kd（L7 的 `per_joint_kd_max=0.10`）+ 重力补偿发帧，所有关节可自由拖动。

## 3. 关闭零力矩后，L7 为什么出问题（根因）

`ZeroTorqueMode(False)`（interface.py:948-1010）退出时：

- L1~L6：本来就是 MOTION_CONTROL，保持原状恢复阻抗控制 ✓
- **L7：检测到"已在 MOTION_CONTROL + 已使能"→ 走 keep 分支（旧代码 :982-990），保持 MOTION_CONTROL 模式，不再回到 PP 模式 ✗**

此后手柄再控制夹爪时：

1. `_gripper_dirty=True` → 控制循环 tick 尾部照发 `set_position_pp(7, ...)`（:536-538）——**L7 已不在 PP 模式，该指令被电机拒绝/无效**；
2. 真正驱动 L7 的变成了每 tick 的 Type 1 运控帧（:464-528）：`kp = _joint_kp.get(7, 80.0) = 80`、`kd = 4.0`——**这是给 6 个臂关节整定的刚度，对夹爪严重过刚**，且失去固件 PP 规划器的速度/加速度限制；
3. 手柄每 10ms 递增目标 ~0.01 rad，kp=80 下每次步进产生 ~0.8 Nm 力矩尖峰 → 咔哒、顿挫、不顺畅；若 LOC_REF 写入在运控模式下被固件当作位置突变指令，还会叠加二次突跳。

**一句话**：退出零力矩时 L7 的运行模式没有恢复（PP→MOTION_CONTROL 后滞留），而正常夹爪控制路径（`GripperCtrl` + PP 指令 + 固件轮廓规划）依赖 PP 模式，于是 L7 落到"运控模式 + 臂级增益 + 无轮廓规划"的错误路径上。

## 4. 已实施修复（方案 A：退出零力矩时恢复 L7 为 PP 模式）

修改文件：`el_a3_sdk/interface.py` 的 `ZeroTorqueMode` 退出分支。

### 4.1 修改点

1. **退出循环范围收窄为 L1-L6**（interface.py:975-1005）：
   ```python
   for mid in range(1, self.NUM_ARM_JOINTS + 1):   # 原为 NUM_JOINTS(7)
       # L1-L6 保持 MOTION_CONTROL，以当前位置为目标开启关节空间阻抗控制
   ```

2. **新增 L7 恢复 PP 块**（interface.py:1007-1025，与 `EnableArm` 对夹爪的配置完全一致）：
   ```python
   gripper_id = self.NUM_JOINTS
   self._driver.disable_motor(gripper_id, clear_fault=False)
   time.sleep(0.01)
   self._driver.set_run_mode(gripper_id, RunMode.POSITION_PP)
   time.sleep(0.01)
   self._driver.enable_motor(gripper_id)
   time.sleep(0.005)
   self._driver.set_pp_velocity(gripper_id, self._pp_velocity)      # 6 rad/s
   time.sleep(0.005)
   self._driver.set_pp_acceleration(gripper_id, self._pp_acceleration)  # 15 rad/s²
   time.sleep(0.005)
   # 以当前位置为 PP 目标保位，避免恢复后夹爪跳动
   self._driver.set_position_pp(gripper_id, current_gripper_pos)
   ```

3. **退出日志更新**：`L1-L6 关节空间阻抗模式（目标锁定当前位置），L7 恢复 PP 位置模式（目标=%.3f rad）`。

4. **函数 docstring 更新**：明确"退出时 L1-L6 保持运控模式；L7 恢复 PP 位置模式（与 EnableArm 约定一致）"。

### 4.2 修复效果

- 退出零力矩后，L7 回到 PP 模式，`GripperCtrl` 的 PP 指令恢复生效，固件重新按 vel/acc 轮廓规划 → 手柄控制夹爪恢复平滑；
- L1-L6 不受影响（保持运控阻抗模式）；
- 修复位于 SDK 层，因此 **debugger 教学面板** 与 **独立运行的 `xbox_control.py`（Y 键零力矩切换）** 同时受益。

## 6. 验证方法

1. 启动 debugger → 连接 → 使能。
2. 手柄控制 L7 开合，确认平滑（基线）。
3. 示教面板点击「开启零力矩模式」→ 手动拖动所有关节。
4. 点击关闭零力矩模式，观察日志：
   ```
   零力矩模式已关闭：L1-L6 关节空间阻抗模式（目标锁定当前位置），L7 恢复 PP 位置模式（目标=xxx rad）
   ```
5. 再次用手柄控制 L7，应恢复平滑（与第 2 步一致）。
