# ACT 模型推理运动问题修复总结

> 日期：2026-08-16
> 涉及文件：`debugger/widgets/camera_pyqt.py`（GUI 推理链路）、`el_a3_sdk/interface.py`（SDK 轨迹执行，只读分析未改动）
> 模型：`ckpt/act_ela3_real`（ACT，chunk_size=10，n_action_steps=10，20Hz）

---

## 一、故障现象

1. 选择 `ckpt/act_ela3_real` 文件夹后模型能加载、能推理（状态栏显示"推理中"），但**点击"开始推理"后机械臂完全不动**。
2. 反复点击「推理一次」，机械臂才会"点一下、动一下"；点「继续控制」后才恢复连续推理运动。
3. 初步修复后机械臂能连续运动了，但**动作非常剧烈、猛冲**。

---

## 二、环境前提

| 项目 | 值 |
|---|---|
| lerobot 版本 | 0.6.1（`VLA` conda 环境；注意 `yolo` 环境的 0.4.4 无法加载本 checkpoint） |
| ACT 动作块 | chunk_size=10，n_action_steps=10，块时长 0.5s（20Hz） |
| ACT state | **8 维** = 末端位姿 7 维 + 夹爪力矩 1 维（训练时并入，见 `train_act_real.py`） |
| ACT 图像输入 | **512×512**（训练时 `--image_size 512`；checkpoint config.json 里的 720×720 是数据集原始分辨率，不是训练输入） |
| ACT 归一化 | 无外部 pre/post processor（checkpoint 中无 `policy_preprocessor.json`），策略直接吃原始输入 |
| SDK 控制循环 | 200Hz，轨迹由 `_execute_trajectory_async` 执行 |

## 三、修复一：ACT 模型接入（前置工作）

原 GUI 只支持 SmolVLA。ACT 与 SmolVLA 推理路径的差异及处理：

| 差异点 | SmolVLA | ACT（修复后处理） |
|---|---|---|
| 归一化 | 外部 `policy_preprocessor/postprocessor.json` | 无外部处理器，跳过加载 |
| `_get_action_chunk` 方法 | 有（用于多次采样平均包装） | 没有 → 包装加 `hasattr` 保护，否则 `AttributeError` |
| state 维度 | 7 维（力矩独立键） | 8 维，力矩拼接到 state 末尾 |
| task 文本 | 需要 | 不需要（ACT 无任务条件） |
| 图像尺寸 | preprocessor 内部处理 | 推理侧显式 `cv2.resize` 到 512×512 |

实现方式：`VLAInferenceThread.run()` 读取 checkpoint `config.json` 的 `type` 字段自动识别 `"act"`；新增 `_build_batch()` 集中处理上述差异；普通/RTC/「推理一次」三条路径共用。

## 四、故障一：连续推理机械臂不动

### 4.1 排查过程（排除法）

1. **手柄抢控制权（第一嫌疑，后被排除）**：手柄连接时 `XboxArmController` 以 100Hz 直接调 `arm.JointCtrl` 保位（绕过 worker 队列），会覆盖 VLA 的 20Hz 指令。已加"启动推理即自动接管控制权"修复。但**用户确认手柄未连接**，问题依旧 → 排除。
2. **观测缺失**：`_vla_get_obs()` 返回 None 时推理循环静默空转。已加"等待有效观测"可见提示。真机上观测正常（「推理一次」能动可证）→ 排除。
3. **控制暂停位**：`_vla_control_paused` 卡 True 会丢弃动作。核查所有置位路径（手柄互锁/单次执行）→ 启动时为 False → 排除。
4. **无头复现**：用假观测驱动 `CameraWidget` 全链路测试，普通/RTC 模式均有 700+ 次 `end_pose_ctrl` 下发 → **动作流确实到达了机械臂 worker** → 问题在 SDK 执行侧。

### 4.2 真正根因：MoveJ 保位段 + 轨迹替换 + 20Hz 下发

普通模式（未勾 RTC）旧代码下发参数为 `servo=False`，走 SDK `MoveJ` 路径，三个机制叠加导致机械臂**永远不动**：

```
SDK MoveJ（控制循环模式）每段轨迹结构：
┌──────────────┬─────────────────────────┐
│ 50ms 保位段   │  S 曲线运动段            │   ← 保位段：保持当前反馈位置不动
└──────────────┴─────────────────────────┘

_execute_trajectory_async：新轨迹【直接替换】旧轨迹（_traj_index 清零重计）

VLA 20Hz 下发 = 每 50ms 来一条新 MoveJ：
t=0ms    轨迹A开始 → 处于保位段
t=50ms   轨迹B替换A → 重新进入保位段      ← A 的 S 曲线段永远没执行到
t=100ms  轨迹C替换B → 重新进入保位段
...      机械臂永远处于某段轨迹的前 50ms 保位段内 → 完全静止
```

**为什么「推理一次」能动**：单段 chunk 的 10 条命令发完后没有新命令再来替换，最后一条命令的保位段结束后 S 曲线完整执行 → 机械臂运动到 chunk 末端位姿。这就是"点一下动一下"的原因。

**为什么 RTC 模式一直正常**：RTC 走 `servo=True` 的伺服流（`_servo_stream`），关节空间线性插值上采样到 200Hz，**没有保位段**——此前 SmolVLA 一直勾着 RTC 用，所以从没踩到这个坑。

### 4.3 修复

`_dispatch_vla_action()` 中 `end_pose_ctrl` 的 `servo` 参数由 `self._rtc_mode` 改为恒 `True`（SDK 伺服流本来就是为 ≥20Hz 连续下发设计的）。

## 五、故障二：修复后动作剧烈、猛冲

### 5.1 根因

`servo=True` 的 20Hz 逐点滴灌虽然能让臂动，但每 50ms 一段的线性插值，其速度前馈为 `Δq / 0.05s`。而 ACT 输出存在 **chunk 边界跳变**（开环执行 10 步后重新推理，新 chunk 首帧与上一段尾帧不连续，离线评估图上可见明显锯齿），每个边界都在 50ms 窗口内被放大成一次**速度脉冲** → 宏观表现就是动作猛烈、抖动。

### 5.2 最终方案：顺序块执行（类 MoveJ 插值）

按"参考推理一次、像 MoveJ 一样插值、执行完一轮再推理下一轮"的要求，普通模式重写为**顺序块执行**：

```
推理整段 chunk(10 步)
   ↓
取 chunk 末端位姿，一次性下发 end_pose_ctrl(servo=False)
   → SDK MoveJ：S 曲线插值（加速度受限、平滑启停），整段只发一次
   ↓
夹爪按 chunk 内序列 20Hz 滴灌跟随（开合时机不丢失）
   ↓
执行窗口（0.5s）结束 → 推理下一段 → 执行 → 循环
```

要点：

- **每 0.5s 只有一条完整 S 曲线**，从机制上消除了 20Hz 滴灌的边界猛冲；新段到来时旧 S 曲线若未走完，从当前反馈位置重新规划（位置连续 + 50ms 保位段过渡）。
- **安全限幅**：每段末端位置跳变 ≤ 10cm（`_seq_max_jump`）、姿态 ≤ 0.6rad（`_seq_max_rot`），沿当前位姿方向等比缩放，防异常输出猛冲。
- **「推理一次」同步改造**：主运动同样一次 MoveJ 到位；20Hz 定时器只保留夹爪跟随和目标/反馈日志（诊断能力不变，仍存 `inference_once_logs/<时间戳>/`）。
- **暂停/恢复/停止适配**：暂停时停止调度定时器（已下发的 MoveJ ≤0.6s 自然走完）；恢复时基于最新观测立即请求新 chunk。
- 推理线程统一为"按需 chunk 推理"循环（`predict_action_chunk`），普通/RTC 共用；普通模式不再逐帧 `select_action` 滴灌。
- **RTC 模式不变**（异步执行 + 软融合，`servo=True` 滴灌）。

## 八、经验与注意事项

1. **20Hz 设定点流不能用 `servo=False`（MoveJ）下发**：SDK MoveJ 的 50ms 保位段 + 轨迹替换机制决定了它只适合一次性运动指令，不适合连续滴灌。连续流式控制必须走 `servo=True` 伺服流，或像本方案一样按 chunk 一次性下发。
2. **ACT chunk 边界跳变是真实存在的**（离线评估 rz 维度可见 ±0.2~0.4 rad 锯齿），执行侧必须做整段插值或时序集成/软融合，不能逐点直发。
3. **顺序块执行 vs RTC**：顺序块平滑但有段间微停顿（S 曲线归零速 + ~50ms 推理）；RTC 无停顿但需调平滑参数。追求平稳用普通模式，追求连续用 RTC + 低通滤波。
4. 可调参数：`_seq_max_jump`（每段最大位移，默认 0.10m）、`_seq_max_rot`（每段最大姿态变化，默认 0.6rad）、`_lerobot_fps`（20Hz，决定执行窗口 0.5s）。
5. 若以后想用中间检查点，直接把完整路径填进模型框，如 `./ckpt/act_ela3_real/checkpoint_step_18000`。
