# 2026-09-21：当前双臂任务规划

## 1. 当前阶段定位

双臂基础设施阶段已经完成，当前不再把主要时间投入到单臂遥操、单臂数据采集或重复的单臂训练验证。

当前已具备的基础：

- 两台真实 EDULITE_A3 可同时连接和控制；
- Joy-Con L/R 可分别遥操左右机械臂；
- 双臂 XYZ、末端姿态和夹爪控制已完成真机验证；
- 双臂上位机、LeRobot 数据接口和 VLA 软件适配已经完成；
- 双臂统一数据接口已经确定为 3 cameras + state[14] + torque[2] → action[14]。

因此当前主线正式转入：

```text
双臂协作任务
→ Joy-Con 双臂演示
→ 双臂真实数据采集
→ 数据质量检查
→ 双臂 VLA 训练
→ 真机协作任务验证
```

## 2. 当前优先级

### P0：双臂协作任务与演示

首先选择真正需要两只机械臂参与的协作任务，而不是两只机械臂各自完成互不相关的单臂动作。

近期先保证任务可以稳定、重复地由 Joy-Con 完成，再逐步提高难度。后续正式实验应选择能够体现双臂协同价值和模型能力的任务。

当前目标不是继续证明“双臂能动”，而是完成至少一个完整的双臂协作演示。

### P0：第一批双臂真实数据

双臂演示能够稳定完成后，立即开始录制测试 episode。

测试数据首先用于验证：

- 三路相机是否同步、语义是否固定；
- `observation.state` 是否为 14 维；
- `observation.gripper_torque` 是否为 2 维；
- `action` 是否为 14 维；
- 左右臂顺序是否始终一致；
- `20 Hz` 与 `action[t] = state[t+5]` 是否继续成立；
- task 文本、视频、Parquet 与 Meta 是否完整；
- 双臂动作是否存在碰撞、操作死区或明显不顺手的情况。

第一批数据只用于链路和任务可采性验证，不直接作为最终大规模训练数据。

### P1：固定正式采集规范并批量采集

测试 episode 通过后固定：

- 双臂任务定义；
- 物体与目标区域；
- 三路相机的固定语义和物理位置；
- 左右臂起始姿态；
- episode 开始/结束条件；
- 成功/失败判据；
- 操作时长范围；
- 异常 episode 的剔除规则。

随后再进行正式双臂数据批量采集。

### P1：双臂 VLA 训练与真机验证

正式数据完成质量检查后：

```text
双臂数据集
→ 云端训练/微调
→ checkpoint
→ 离线推理检查
→ 14 维 action 输出验证
→ 双臂真机协作执行
→ 成功率与失败案例统计
```

这一阶段再进入双臂模型能力验证，不再优先追加新的单臂训练轮次。

## 3. 暂不作为当前主线的内容

### VR

老师已有 VR 控制路线和笛卡尔控制参考程序，当前没有必要为了体验路线而单独重复搭建 VR。

现阶段继续使用已经验证可用的 Joy-Con 完成双臂演示和数据采集。后续如 Joy-Con 在复杂任务上明显限制操作质量，再评估是否切换或接入 VR。

### 移动底盘

移动底盘属于后续系统扩展项。

当前先完成双臂协作任务、双臂数据和双臂 VLA 真机验证，待双臂主线稳定后再考虑加入底盘，不让底盘开发打断当前采集和训练节奏。

### 单臂重复训练

单臂链路此前已经完成验证，当前不继续以“再采一批单臂数据、再训练一轮”作为主要工作。

除非双臂调试需要做最小对照实验，否则资源优先投入双臂。

## 4. 任务选择原则

后续双臂任务应同时满足：

1. **确实需要双臂协作**：单臂难以等价完成；
2. **可以重复采集**：场景能够快速复位；
3. **Joy-Con 可操作**：当前遥操方式能够稳定完成；
4. **成功标准明确**：便于数据筛选和实验统计；
5. **具有展示价值**：正式实验阶段能够体现双臂 VLA 的能力，而不是简单的双臂独立动作。

任务难度采取“先跑通、再提高”的方式：先验证双臂协作数据链路，再在正式实验任务中增加协同难度。

## 5. 当前最近一步

当前最近一步只有一个：

> **确定第一个双臂协作任务，并用 Joy-Con 完成多次完整真机演示。**

演示稳定后立即进入第一批双臂测试 episode 采集。

后续暂不优先切换 VR，也暂不接移动底盘。
